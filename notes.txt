I don't have to create a map object and store objects in that

I can just store each notable object in the database with x-y coordinate columns

-> No search latency i..e iterating through a 2d matrix for an object
-> Simplifies distance calculations

This means that every object that interacts with the database instead of a map requires a connection to be passed into them upon creation
They also don't serve any purpose beyond initialization of the data





Items have the following data:
 - Market Price (Standardized Price Across all markets to be assigned a modifier upon town creation)
 - Weight Per Unit (Determines the max amount that can be transported per player caravan level)
 - Class (Is it an Unprocessed or Processed Good?)
 - Type (Type of Un/Processed Good e.g. Food, Metal, etc)
 - Expiry Date (Only Applies to Foodstuff)
